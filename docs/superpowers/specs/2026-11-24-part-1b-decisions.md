- **Spec:** `docs/superpowers/specs/2026-11-23-dsa-playbook-design.md` (approved). Part 1b = "Quiz, flashcards, drills, tracker, Today and the dashboard" (§15).

## D1. Curriculum catalog (the planned road)

The dashboard must show the real "X of Y, Z left" for the WHOLE course, not just the built part. The owner asked for "a dashboard where I know what I have learned till now and how much is left, so that completion will be more valuable".

- `content/catalog/modules.ts`: all 26 modules from spec §5. Fields: `id` (kebab-case, e.g. `foundations`, `arrays-strings`, `hashing`, `two-pointers`), `order` (1 to 26), `level`, `icon`, `title`, `part` (from §15 and `docs/curriculum/problem-map.md`).
- `content/catalog/lessons.ts`: the planned lessons of every module. Fields: `id`, `moduleId`, `title`, `minutes`, `patternId?`.
  - Foundations uses the spec §5 draft list.
  - The other modules get one lesson per pattern or idea, based on each module's "Teaches" line in the problem map and spec §5. Aim for 3 to 6 lessons per module and 15 to 30 minutes each.
  - These ids are drafts until that module's part starts. They must still be valid kebab-case and unique.
- `content/catalog/patterns.ts`: `Pattern { id, moduleId, lessonId, title }` (spec §11.2). Every pattern lesson has one pattern.
  - The existing problem `contains-duplicate` uses `patternIds: ['hashing']`. Keep that id. It belongs to module `hashing` and its HashSet lesson.
- `content/catalog/problems.ts`: all 319 problems of `docs/curriculum/problem-map.md`.
  - Fields: `id`, `title`, `moduleId`, `difficulty`, `patternIds`, `sheets`, `url`, `lc?`, `core`.
  - `id` is the LeetCode slug (e.g. `contains-duplicate`), or the kebab-case title for a GfG-only problem.
  - `patternIds` maps each problem to 1 or 2 catalog patterns.
  - `sheets` values are `neetcode150`, `striver-bs` and `striver-recursion`.
  - `core` marks 1 to 3 core problems per pattern. Every pattern needs at least one.
  - The file is generated by a committed script, `scripts/build-catalog.mjs`. It parses the problem map tables and holds the `patternIds` and `core` mapping in its own table. CI runs `node scripts/build-catalog.mjs --check` to make sure the file is up to date.
- **Built content** (`content/index.ts`) stays the source for real modules, lessons and problems. The registry merges built and planned content.
  - A catalog item whose id is built links to the real page.
  - Any other catalog item shows "coming in Part N".
  - A built id that is missing from the catalog is a content-check error.
- `content/sheets/neetcode150.ts`, `striver-bs.ts` and `striver-recursion.ts` hold ordered problem ids.
  - The Striver order is the `#NN` numbers in the problem map's Source column.
  - The NeetCode 150 official order (from `neetcode-gh/leetcode` `.problemSiteData.json`, the data behind neetcode.io/practice) is below.

## D2. Progress in the store

These fields are added to `dsa:v1`. Fields are only ever added, never renamed.

- **New fields on `StoredState`.** Every item has an `updatedAt` (spec §11.3), and `normalize()` validates every field.
  - `lessons`: `Record<lessonId, { openedAt; bestScore; total; passedAt?; updatedAt }>`
  - `problems`: `Record<problemId, { marks: { understood?; solvedAlone?; selfMarkedAlone?; canExplain?; fromMemory? } (timestamps); solvedAt?; solvedElsewhere?; revealedAt?; resolveSteps (0 to 3 done); nextResolveAt?; updatedAt }>`
  - `cards`: `Record<cardId, { box: 1|2|3|4|5; dueDay: "YYYY-MM-DD"; again: number; lastDay; updatedAt }>`
  - `drills`: `Record<attemptId, { itemId; patternIds; correct; at }>`. Only the newest 1,000 are kept. It is a record, not an array, so the 3-way merge keeps entries from two tabs.
  - `days`: `Record<"YYYY-MM-DD", number>`. Activity per local day, for the streak and the 12-week grid.
- **Time.** Engine functions take `now` (ms) or a `today` day key. They never call `Date.now()` inside. A helper `dayKey(ms)` uses local time.
- **Fold-ins from `docs/notes/part-1a-followups.md`:**
  - A corrupt stored value is backed up only once.
  - The pending code save is flushed on `pagehide`.

## D3. Tracker (spec §9.1, §9.2)

- The problem page has a "Your progress" box with these controls:
  - ticks for levels 1, 3 and 4
  - "I solved this elsewhere"
  - "Mark solved alone" (self-marked, shown with a tag)
- Level 2 is set automatically (see below). Level 5 is computed, never stored.
- The first press of **Show solutions** stores `revealedAt`.
- `LabDeps` gets `onSubmitResult(result)`. When Submit passes every test:
  - `solvedAt` is set (first time only).
  - `marks.solvedAlone` is set if `revealedAt` is not set.
  - The re-solve schedule starts or moves on: +3, +7 and +21 days after the first solve. A Submit pass on or after `nextResolveAt` completes the next step.

## D4. Lessons and quizzes

- Opening a lesson sets `openedAt`. That marks the module as "started".
- The lesson quiz `onComplete(score)` saves the best score. A score of 2 of 3 or better sets `passedAt`, which means "lesson done".
- **Module page:**
  - It shows the module quiz: multiple choice, plus scenario questions with "show answer, then mark yourself right or wrong".
  - Each lesson and problem shows its progress.
  - A "Mixed drill for this module" button opens `#/drills/<moduleId>`.
  - An empty module quiz is hidden.

## D5. Flashcards (spec §9.5)

- `src/engine/cards.ts` builds the cards from content, with the 8 kinds from the spec.
  - A card id is `<sourceId>:<kind>`.
  - For list fields it is `<sourceId>:<kind>-<index>`. The content check warns if an item is removed from the middle of such a list, because that would shift the ids.
- Scheduling is Leitner with 5 boxes and intervals of 1, 3, 7, 14 and 30 days. Again, Hard, Good and Easy follow §9.5 exactly.
- **Decks:**
  - Due today
  - By module
  - Weak spots
  - Interview tomorrow (hooks and traps, about 10 minutes)

  Only cards from started modules appear.
- **Pages:** `#/cards` picks a deck, and `#/cards/<deck>` runs the review.
  - Space or a tap flips the card. Keys 1 to 4 rate it.
  - The flip is a fade and colour change only. With reduced motion there is no animation.
  - The page shows "X left today".

## D6. Spot-It drills (spec §6.2)

- **Items.** The `DrillItem` type is `{ id, kind, prompt, limits?, acceptedPatternIds, clueExplanation, moduleId }`.
  - Hand-written items live in `content/drills/<moduleId>.ts`. Foundations gets a few now: real-life and look-alike items, in simple words.
  - `interview` items are also GENERATED from built problems. They use the spot prompt and limits, with the title hidden. The accepted answers are `problem.patternIds`.
- **A session:**
  - It has 10 items, or fewer if fewer exist.
  - Each item has 60 seconds. Running out of time counts as wrong.
  - Items come from patterns in started modules, weighted toward weak patterns.
  - The options are pattern titles: the accepted ones plus distractors from other catalog patterns, at least 4 in total. A seeded shuffle keeps the tests stable.
  - Feedback always shows the clue explanation.
- **Pages:** `#/drills` (mixed) and `#/drills/<moduleId>`.

## D7. Mastery and fading (spec §9.3)

Pure functions in `src/engine/mastery.ts`:
- `patternStatus` returns `not-started`, `learning`, `practicing`, `mastered` or `fading`.
- `lessonDone`
- `problemLevel`, which includes the computed level 5
- `isMastered`

## D8. Dashboard (spec §9.4)

- `#/dashboard` is read-only. It shows everything in §9.4. The "Y" numbers come from the catalog.
- All the math lives in pure functions in `src/engine/dashboard.ts`.
- Hours left come from lesson minutes plus a time per problem: Easy 20, Medium 40, Hard 60 minutes.

## D9. Today page

- `#/` becomes Today. It shows:
  - cards due
  - problems to re-solve
  - a mixed-drill button
  - "continue where you left off"
- A first-time visitor sees the current intro and a "Start with Foundations" button.

## D10. Other pages and navigation

- `#/roadmap`: all 26 modules by level, built and planned, with progress.
- `#/sheets/<sheetId>`: the sheet in its original order. Each problem shows its status, or "coming in Part N".
- `#/settings`:
  - theme
  - Export progress and Import progress, as a JSON file. Import validates with `normalize()` and asks before it replaces anything.
  - The note "Sync comes later".
- **Router:**
  - New routes: `dashboard`, `roadmap`, `drills` (plus an optional module), `cards` (plus an optional deck), `sheets/<id>` and `settings`.
  - `allRoutes()` includes them, so the e2e no-console-error test covers them.
- **Shell:** a compact top nav with Today, Dashboard, Cards, Drills and Roadmap. The sidebar shows a progress dot for each module.

## D11. Content-check additions

- Every built module, lesson and problem id is in the catalog. Each built problem's `patternIds` and `sheets` match the catalog.
- Drill items follow the writing rules, and their `acceptedPatternIds` exist.
- Every pattern has at least 1 core problem.
- Sheets only use catalog ids. NeetCode 150 has exactly 150 ids.

## Git workflow (spec §15.2)

- Work happens on branch `part-1b`.
- The controller commits once per reviewed task, with a message like `<type>(<scope>): <summary> (Part 1b Task N)` and the Claude co-author trailer.
- At the end there is ONE pull request into `main`. The controller never merges it. The owner reviews in the browser, then merges.
